# v9.2 revision plan — relations & provenance completion

Status: **draft, ready for review** — no code has been changed by this document.
Line numbers refer to the working tree at `2a62002` (post-#10/#11 merges) and
must be re-checked at implementation time.
Audit evidence: live Hub tip `bc9eab28…` (tag `v9.1`), data commit
`ed7576b6…`, 3,302 rows; verified against the read-only local HF cache and
read-only Hub reads on 2026-10-05.

## 1. Why v9.2

The v9.1 quality revision (mailroom-issues#196 Phase B) fixed the blind-surface
leaks and published presence/budget codes. The follow-up audit ("schema ↔
consumer gap report", 2026-10-05) found three classes of remaining defects:

1. **Provenance is wrong on 1,541 published rows** (P1 correctness).
   `eval_contract.annotation_provenance` reads a *top-level* `intent_source`,
   but v9/v9.1 nest it inside `gt_fields` — so the published `ground_truth`
   config ships only `source_native` (2,202) + `synthetic` (1,100) instead of
   the six regimes the repo's own full-snapshot test already expects
   (`tests/test_eval_contract.py:161-184`):
   `verified_join` 162 · `llm_zero_shot` 637 · `human_annotated` 96 ·
   `synthetic` 1,100 · `heuristic` 646 · `source_native` 661.
   `annotation_model`/`confidence`/`reviewer` are empty corpus-wide.
2. **Relations and matter lists are empty or split-brained.**
   - `related_document_ids` has **no producer at all**: 0/3,302 (top-level)
     and 0/3,302 (nested mirror). The 23 rows in 9 heuristic matter threads
     carry no relation targets.
   - `gt_fields.relationships` / `gt_fields.related_document_ids` are
     permanent `"[]"` placeholders even where the top-level value is real
     (14 rows) — `v9_build.complete_gt_fields:399-401` writes the
     placeholders *before* `hardened.enrich_gt_rows` runs `matter.py`, which
     only writes top-level columns.
   - Bundle relation targets are filenames, not `document_id`s
     (`bundles.py:183`), and bundle anchors have **no back-links**.
   - Stream distractors are stripped of matter scalars but keep
     `relationships`/`related_document_ids` (`hardened.py:144-151`).
3. **Build-internal and stale surfaces.**
   - `_published` (a v8→v9 migration artifact) ships in the published
     `ground_truth` parquet on 2,000 rows (`v9_build.py:841-843`,
     `hardened.stage_configs:179-181`). It is undocumented on the card and
     stripped only from the JSONL sidecar.
   - Fixtures never receive identity fields (`hardened.build_fixture_rows:157-163`
     skips `identity.enrich_row`) and falsely claim class-source provenance
     (`annotation_source` = class corpus, `annotation_method` = `source_native`)
     despite being `synthetic=true`.
   - Three stale 27-key GT registries can silently drop all five v9.1 keys on
     rebuild: `run_all.py:79-89` (P5), `dataset_export.stage_parquet:103-114`
     default, `intent_backfill.GT_PUBLISH_KEYS:589-599`.
   - The v9.1 leak-fix is contradicted by the dataset card
     (`docs/dataset-cards/mailroom-dataset.md:82-89` still documents
     `metadata.clause_count` and a 27-key schema).

Scope: **code-only revision over the live v9.1 data commit. No new document
sourcing, no LLM/GPU credentials.** Zero row-set / identity / content drift:
`document_id`, `content_sha256`, `normalized_text_sha256`, `doc_text`, and
every metadata key are byte-identical before/after; the only GT columns that
may change are enumerated in §4 (zero-drift law).

Two deliverables:

- **v9.2** = Workstream C (core, §3): `default` + `ground_truth` +
  `ground_truth_hardened.jsonl` + card + manifest. Shippable on its own.
- **v9.2b** = Workstream S (stage-config overlay, §5): `bundles`/`streams`/
  `fixtures` column completion, **row-set preserving** (no resampling).
  Gated on D8; may ship in the same publish or defer to v9.3 without
  blocking v9.2.

Everything else the audit found — the 91 EX-10 `pending_annotation` queue,
the 796 `heuristic_provenance` labels, `source_revision` sourcing for the
2,802 empty rows, duplicate/cross-split policy, downstream re-pinning — is
explicitly out of scope (§9).

## 2. Decision log

| # | Decision | Rationale |
|---|---|---|
| D1 | `related_document_ids` values are **`document_id`s**; the matter producer falls back to `filename` only for bare (un-enriched) unit rows. | The §84 chain always runs `identity` before `matter`, so published rows always get ids; fallback keeps pure unit tests readable. |
| D2 | `annotation_source` prefers the published `source_corpus` column when present, falling back to the class map. Fixes 91 EDGAR rows (`theatticusproject/cuad` → `sec_edgar`). | `identity.source_corpus` already applies the EDGAR/LOB override rules; annotation provenance must be joinable to identity. |
| D3 | Keep **both** the top-level matter columns and the nested `gt_fields` mirrors, and make the mirrors canonical copies (written by `matter.enrich_rows`). | Consumers already read the nested JSON surface; removing mirrors is a breaking schema change; `"[]"`-forever is the actual bug. |
| D4 | Drop `_published` from the published GT parquet. | Build-internal, undocumented, leaked to consumers; the v8 values remain recoverable from the frozen `mailroom-corpus` repo. Enforced at staging (`_`-prefixed keys filtered) so it cannot return. |
| D5 | `gt_presence` is **not** extended to relations/matter fields. | `gt_presence` classifies class-relevant *label* fields (`FIELD_KEYS_BY_CLASS`); relations are cross-class structure, not per-class GT. Documented in the card instead. |
| D6 | Merger specialist routing divergence (published `contracts_specialist` vs. newer taxonomy `merger_agreement_specialist`) is **not changed here**. | It is a consumer/taxonomy alignment decision with its own card; v9.2 must not silently churn 152 published values. |
| D7 | Content-duplicate / cross-split policy is **documented, not changed** in v9.2. | The md5(filename) split rule is a stability law; changing it needs a sourcing/policy card, not a revision. |
| D8 | Workstream S ships as `v9.2b` only if every gate in §5 is green; otherwise it is planned as v9.3. | Keeps v9.2 small, verifiable, and independently releasable. |
| D9 | The revision recomputes **only** the 7 `annotation_*` columns + matter relations + `_published` removal — never `expected_specialist`/`expected_stage`/review/retry. | The specialist registry can diverge when a sibling taxonomy checkout exists; recomputing routing fields would churn published truth (D6). |

```python
def resolve_bundle_relations(rows: list[dict]) -> None:
    """Canonicalize §14 relation targets to document_id: siblings → anchor
    id; anchors gain back-links to every member id (bidirectional graph).
    Rows must already carry identity/document_id."""
    id_by_fn = {str(r.get("filename") or ""): str(r.get("document_id") or "")
                for r in rows}
    by_matter: dict[str, list[dict]] = {}
    for r in rows:
        by_matter.setdefault(str(r.get("matter_id") or ""), []).append(r)
    for members in by_matter.values():
        for row in members:
            if str(row.get("group_role") or "") == "primary":
                targets = []
                for member in members:
                    if member is row:
                        continue
                    ident = id_by_fn.get(str(member.get("filename") or ""), "")
                    if ident:
                        targets.append(ident)
                row["related_document_ids"] = targets
            else:
                anchor_id = id_by_fn.get(str(row.get("bundle_anchor_filename") or ""), "")
                if anchor_id:
                    row["related_document_ids"] = [anchor_id]
```
