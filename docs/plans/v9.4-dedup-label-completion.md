## 1. Decisions

- **D1, the row set changes** (3,302 → 3,292; train 2,971 / test 321): 9 exact copies
  plus 1 cross-split near-duplicate test row (D2a). This is the
  first revision since v9 that removes rows. It is a dataset-content change and
  needs a new revision tag at promotion.
- **D2, survivor rule.** In order:
  1. richest annotation (CUAD spans + MAUD answer count + populated presence cells);
  2. no copy marker such as `(1)`;
  3. `train` split;
  4. smallest filename.

  A verified upstream defect overrides the rule (`UPSTREAM_DEFECT_SURVIVORS`, keyed by
  the full `content_sha256`; see D3). The override must name exactly the group's
  members, or staging fails instead of falling back to the rule, and gate (a) checks
  the staged survivor against it.

  Survivors keep their v9.3 bytes, `document_id` and split. `dedup_removed.jsonl`
  ships in the payload with every removed copy, its survivor and any label conflict.
- **D2a, cross-split near-duplicates leave test (decided 2026-11-05).** After exact
  dedup, a test row whose normalized text (`identity.normalize_text`: NFC, line
  endings, whitespace runs) equals a train row's is dropped. Keeping it would leak
  training text into test, and the md5 split rule forbids moving it. The one case is
  the EX-3 board resolution `0000950137-06-011083_n08078exv3w03.htm` (test). It
  differs from its two train siblings by 2 whitespace characters in the signature
  block, its labels are identical, and nothing references it. The drop set is pinned
  (`EXPECTED_NEAR_DUP_TEST_DROPS`), so a different set fails the build. Its
  `dedup_removed.jsonl` record has `kind = near_duplicate_test_drop`. Gate (a)
  recomputes the normalized hash from both texts and checks test → train. A
  near-duplicate never lends its CUAD journal record to the survivor (the offsets
  differ). Same-split near-duplicates stay, report only.
- **D3, conflicting expert annotations are not merged.** Two groups have identical
  text but different expert labels:
  - CUAD `ADUROBIOTECH…CONSULTING AGREEMENT(1).PDF` has 16 spans; the non-`(1)` copy
    has 14. The richer `(1)` copy survives.
  - MAUD `contract_148` / `contract_149` disagree on 15 of 17 shared questions and on
    `expected_subclass` (`mixed_cash_stock` vs `other`). **Resolved (2026-11-05):
    `contract_148` survives, by upstream-defect override.** The duplicate is MAUD's,
    not ours:
    - in the canonical MAUD v1 release (Zenodo record 7500064, `maud_v1.zip`),
      `data/contracts/contract_148.txt` and `contract_149.txt` are byte-identical
      (Kimco Realty / Weingarten Realty, April 15, 2021; 358,253 chars). It is the
      only identical pair among MAUD's 152 contracts. The HF mirror
      `theatticusproject/maud` ships 100 contract files and has no `contract_149`;
    - MAUD's own evidence excerpts (`MAUD_{train,dev,test}.csv`), matched with
      punctuation, case and spacing ignored: **57 of 71** `contract_148` excerpts
      occur in the text (Type of Consideration "Mixed Cash/Stock", right for this
      deal), and **0 of 75** `contract_149` excerpts do. `contract_149`'s answers
      describe an all-cash agreement whose text MAUD never shipped.

    The richness rule would have kept `contract_149` (187 answers vs 156), so it
    would have kept labels that do not describe the document. Our rows store MAUD
    answers only, not excerpts, so the corpus cannot see this on its own.
    `scripts/audit/verify_maud_duplicate.py --check` re-derives the evidence from
    Zenodo (network-only, outside the build). Still 9 exact copies removed.
    The surviving row's `expected_subclass` is `mixed_cash_stock`.

    Follow-ups, out of scope here: report the packaging defect to The Atticus
    Project, and source the real `contract_149` agreement (for example from EDGAR)
    to restore 152 merger rows. That is new sourcing for a later revision.
- **D4, `"N/A"` stays.** The 3 CMS outpatient `"N/A"` dates are a verbatim source
  marker (`v9_build`), not a placeholder.
- **D4a, labeling model: `Qwen/Qwen3-32B-FP8` on one H100 (decided 2026-11-05).**
  The first pass used `Qwen/Qwen3-14B-AWQ`, and it is **retired** for ground truth:
  - 126 of its EX-10 spans failed basic re-verification;
  - the review spot check found it mixing up categories (a tax clause as Audit
    Rights, a survival clause as Covenant Not To Sue, expense reimbursement as
    Insurance);
  - the sandbox's own benchmarks put small Qwen3 CUAD presence F1 at 0.57–0.64
    (SAND-032 / SAND-042).

  `Qwen3-32B-FP8` is the strongest model in the sandbox matrix
  (`config/models.yaml`) that keeps the 32k window on one GPU without tensor
  parallelism. The sandbox posture (`gt_labeler.POSTURE`) pins it, and
  `assert_posture` refuses the 14B. Here, `LABEL_MODEL` / `APPROVED_LABEL_MODELS`
  make it the only model whose records are read at all; other models' records are
  dropped before folding, and the 14B journal is no longer auto-discovered.
  A bigger model is a better bet, not proof. D7 decides. If the 32B fails
  calibration, the next step is the 70B tier (2×A100-80GB, TP=2), which needs a
  new sandbox posture.
- **D5, LLM labels are never trusted, only verified.** Serving lives in
  `local-mailroom-sandbox` (SAND-045, `sandbox-vllm-gt-labeler`,
  `Qwen/Qwen3-32B-FP8`). This repo only re-verifies journals. A label is ingested
  only when:
  0. the record comes from `LABEL_MODEL`, that model has **passed calibration**
     (D7), and the record names the same `document_id` as the row it is filed
     under; the journal's sha256 and models are recorded in the audit;
  1. every span equals `doc_text[start:start+len(text)]` in *this* payload, at a
     non-negative offset inside the document;
  2. every category is one of the 41 CUAD names read from the golden rows;
  3. spans are 4,000 chars or shorter, and `Document Name` sits in the opening 5,000 chars;
  4. light semantic probes pass, and a span is more than the category's own heading.
     The probes: Governing Law mentions law/governing/jurisdiction; date categories
     carry a date or event trigger; Audit Rights mentions audit/inspect/books/records/
     examine; Insurance mentions insurance; Covenant Not To Sue mentions sue/suit/
     claim/challenge/contest; Affiliate License-* mentions both affiliates and a
     license; Source Code Escrow mentions escrow or source code. Failing spans are
     dropped, never repaired;
  5. the labeler's own floor holds after drops (4 or more present categories, plus
     Document Name or Parties).

  Otherwise the row stays `pending_annotation`. A survivor can take the accepted
  record of its removed byte-identical copy (same text, same offsets).
- **D6, intent acceptance.** A relabel is accepted only when both passes agree on an
  in-vocabulary label (pass A: subject + body; pass B: body only), **and** the label
  either confirms the original or both passes have confidence ≥ 0.8. Otherwise the
  row stays `flagged_review`.
- **D7, calibration gates ingest and publishing.** The labeling model is scored
  against expert labels **before** any of its labels enter the stage:
  - CUAD category presence on the fixed 40-contract golden sample
    (`cuad_calibration.jsonl`, stratified, ≤32k band, seed 42): micro-F1 ≥ **0.75**
    **and** micro-precision ≥ **0.80**;
  - intent Cohen's κ ≥ **0.75** on the 96 manual correspondence intents (required
    whenever an intent journal is supplied).

  The floors were 0.6 in the first draft. Small Qwen3 models clear 0.6 (0.57–0.64),
  so it could not tell a weak labeler from a good one. Precision has its own floor
  because a wrong label is worse than a missing one.

  A result counts only if it covers its whole sample (otherwise `incomplete`; a
  labeler reject scores as a miss, not a skip) and comes from `LABEL_MODEL`
  (otherwise `model_mismatch`). Until a journal's calibration passes, that journal is
  **held**: nothing from it is ingested, gate (h) is `PENDING`, and
  `publish_ready = false`.

  Gate (h) does not trust the report. It re-derives the status from the scored
  details, re-scores each calibration journal against the staged expert rows, and
  checks the journal's recorded sha256. A forged status, an edited journal or a
  mismatched score fails the gate. A journal that is not on the verifying machine
  leaves (h) `PENDING`. `publish_ready` means "the labeler is calibrated", not "every
  row is labeled": EX-10 rows whose labels fail verification stay
  `pending_annotation`, and the audit counts them.

## 3. Modal runbook

The operator steps live in **`docs/runbooks/v9.4-modal-handoff.md`**. They run on
the operator's machine: the Modal client speaks gRPC, which the cloud agent's
egress proxy does not support. The queues are committed under
`docs/reports/audits/v9_4_queues/`.

In order, each step gating the next:

0. posture check (`--check`) and a CPU-only weight download;
1. deploy, confirm `/v1/models` serves `Qwen/Qwen3-32B-FP8`, then label the
   40-contract calibration sample;
2. score it locally. **Stop unless CUAD calibration is `pass`.** A fail escalates
   to the 70B tier (D4a); the floors are never lowered;
3. the 89 EX-10 contracts, one chunk per invocation (at most 4 runs);
4. the intent pass, then a re-stage with every journal;
5. gates, then `modal app stop`.

Projected total about $4.60 on one H100 ($3.95/h; calibration about $0.98, EX-10
about $2.64, intents under $1). These are projections, not measurements, so the
runbook hard-stops if measured spend after step 1 exceeds $2.50. Per-invocation
guards: 40 documents, a $2 projected cap and a 45-minute wall cap.

Before any spend, the runbook checks that the operator's locally built stage
reproduces `stage_digest` `2430540f…09c31b`, rebuilt from scratch: v9.3 from the
sha-pinned Hub snapshots, then v9.4.

## 4. Gates (`verify_v9_4_conformance.py`)

- (a) row set: 0 duplicate shas, count = v9.3 minus removed, md5 split rule holds; every
  removed name exists in v9.3 with the same `content_sha256` as its staged survivor.
  A group listed in `UPSTREAM_DEFECT_SURVIVORS` must keep exactly the override's survivor.
- (b) survivors byte-identical to v9.3, except allowlisted fill fields.
- (c) 0 placeholder cells.
- (d) stored `gt_presence` equals a fresh recompute on every row, the key-set law
  holds, no `genuine_gap`.
- (e) every populated EX-10 CUAD map re-verifies verbatim.
- (f) every ground_truth parquet column equals the JSONL row (shared `gt_parquet_record`
  serializer); `dataset_info` features equal the parquet columns. The blind `default`
  config has exactly the 4 label-free columns, the same row set per split, and the same
  `doc_text`.
- (g) manifest sha table recomputes and lists every staged file exactly once.
- (h) calibration, from `v9_4_report.json` only if its `stage_digest` (sha256 over every
  staged file except `manifest.txt`) matches the stage. It is re-derived and re-scored
  from the journals, never read as written (D7). `PENDING` blocks publishing only.

Staging refuses a `--stage-dir` that equals, contains, or sits inside `--base-dir`.
